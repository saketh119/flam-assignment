# Part B4 — Production Confirmation Metric

The single production metric I would instrument is a **KV-cache preemption counter**, measuring the number of sequences preempted because of KV-cache pressure.

The B2 hypothesis predicts that this counter should remain at or near zero around the safe operating point and increase once concurrency exceeds the KV-cache capacity knee.

The benchmark shows:

| Batch | KV utilization | Preempted sequences |
|---:|---:|---:|
| 24 | 0.93 | 0 |
| 32 | 0.97 | 7 |
| 48 | 0.97 | 23 |

Therefore, production telemetry should show preemptions increasing as long-context concurrency crosses the KV-cache capacity knee.

This should coincide with the same behavior observed in the benchmark: increasing latency and degraded throughput.

A matching production signal would support the B2 mechanism that KV-cache pressure and sequence preemption are responsible for the throughput anomaly. If preemptions remain zero while throughput degrades, the KV-cache explanation would need to be reconsidered and another bottleneck investigated.
